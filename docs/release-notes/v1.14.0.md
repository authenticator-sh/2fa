## If you already use the extension, nothing changes for you

This release adds a paid plan, Pro. If you installed the extension before this
version, your installation keeps **unlimited accounts, free**, exactly as
before. You don't need to do anything.

## What Pro is

New installations may have a limit on how many accounts they hold for free.
Pro removes the limit. That is the whole difference:

- **The limit only ever stops adding an account.** Every account you have
  keeps showing its code, and keeps working with export, backups, restoring
  and sync — with or without Pro, and if a Pro subscription ends.
- **It is checked on your computer.** The limit and your license are checked
  locally, from the last data our server signed, so they work offline too: a
  limit already received still applies without a connection. Until the
  extension has reached our server once, nothing is limited.
- **When Pro is offered to you, it appears in Settings.** Paying happens on
  Stripe, in a new tab, with Link as the seller of record. Pro turns on by
  itself in the browser you paid from, and with Chrome sync on, your other
  Chrome profiles turn it on by themselves too. On another computer, enter
  your license key under Settings → Pro; if you have lost it, "Restore a
  purchase" sends it to the email you paid with.
- There is a monthly and a yearly subscription, and a one-time lifetime
  purchase. Which ones you see can differ while we find the right prices.

## What the extension now sends, and what it never sends

To make the free plan and Pro work, the extension checks in with
`api.authenticator.sh` once a day. It sends an anonymous id created by this
installation, the extension version, its language and the browser's, when the
installation appeared and whether that predates this release, **how many**
accounts it holds (a number — never which ones), whether password protection
and sync are on and how the extension opens, which policy and license it holds,
whether it already holds its license key and the last four characters of it,
how many times the extension was opened on each day since the last check-in,
and a short list of billing events such as "the paywall was shown".

It never sends your secrets, account names, issuers, codes, or the sites you
use them on. The id is not linked to your email unless you buy Pro: then the
purchase links it, and any installation where your license key is active, to
the email you paid with. The full list of fields is in the README under "What
is sent to our server", and a test holds the code to it.

When you uninstall, the feedback page now carries the same anonymous id: as it
opens it tells our server that installation was removed, and an answer, if you
give one, is linked to it. Answering is still optional.

## Steam Guard codes

Steam's 5-character codes are a second code type, next to the usual digits.
They come in from:

- **Add → Advanced Settings → Code type → Steam Guard**, with the
  `shared_secret` typed or pasted as it is (Base64 is fine);
- an unencrypted **Steam Desktop Authenticator `.maFile`**;
- other apps' backups: Aegis, 2FAS and andOTP entries of type Steam, Bitwarden
  `steam://` entries, and links in `otpauth://steam/…`, `encoder=steam` or
  issuer `Steam` form.

If you already had the same key as an ordinary 6-digit card, adding it as Steam
turns that card into a Steam one. Steam accounts are not offered for sharing by
link, and CXF export leaves them out and says how many — CXF has no way to
describe them. A text export writes them as `otpauth://steam/…`.

**If you use sync with a computer still on 1.13.3,** that computer shows a
Steam account as a wrong 6-digit code until Chrome updates it to 1.14.0, which
happens on its own within a day or so. Its copy of the account is intact; only
the code it draws is wrong. And sync keeps whichever version of an account a
computer already had, so a computer that held the 6-digit card before keeps it:
add the account as Steam there too.

## Also new

- **Undo after deleting an account.** The account comes back where it was.
- **Order** in Settings: Manual, Service or Name. Dragging to reorder is off
  while the list is sorted.
- **Search also matches group names.**
- **Quick fill finishes the job.** If the extension had to ask you to unlock or
  to pick an account first, the code now goes into the field you right-clicked,
  instead of only being copied. It also finds code fields inside web
  components.
- **Settings is grouped** into Security, Backup & Restore, Account list,
  Browser and Diagnostics. The language picker moved to the footer.
- **The first-run guide** has a row for "I have a secret key", and pasting
  links is part of it.
- **Passwords:** an encrypted export asks for its password twice; a password on
  a shared link must be at least 8 characters; linking a passkey asks for the
  vault password; resetting with the recovery code unlinks the passkey, and
  says so first.
- Real plural forms in every language instead of "account(s)", a darker blue
  and darker greys for contrast, screen-reader labels, keyboard access to
  Import and Choose image, and confirmation dialogs that start on Cancel.

## Fixed

- **Settings the extension cannot generate are refused, not quietly
  replaced.** A link, a Google Authenticator export or another app's file that
  asks for MD5, 4 digits or a 7200-second period used to be saved with the
  defaults and showed a code that never worked. Those entries are now skipped
  with a message; the rest of the import goes in.
- **Sync:** a deleted account no longer comes back after password protection
  is switched on or off; a repaired "Invalid key" account no longer returns as
  a duplicate; a save no longer drops an account another computer had just
  added.
- **The list** no longer shows a spinner or jumps to the top after adding,
  editing or deleting.
- **Clock correction:** the side panel and the floating window no longer lose
  the correction for good after one failed check; when the correction lapses,
  the card says "Checking the time…" instead of showing a code that is probably
  wrong; Copy computes the code at the moment of the click.
- **"Ask for password: Every time"** really asks every time now: the unlocked
  key used to stay in the browser's session storage.
- **Quick fill:** the per-site memory now knows that tenants of shared domains
  (github.io, go.kr and the like) are different sites — some sites will ask
  once more which account to use; a right-click inside a frame the extension
  cannot reach no longer fills a field on the page around it.
- **Escape** closes only the dialog on top, not the screen under it as well.
- A damaged authenticator QR code gets its own message instead of a scanner
  that keeps retrying; Google Authenticator exports no longer produce names like
  "Issuer: Issuer:account".
- An encrypted backup file with an absurd iteration count is refused as damaged
  instead of freezing the popup.
- A failed copy says so; a settings switch that failed to save flips back;
  choosing the same file twice works.
- **CXF export** now writes the published CXF 1.0 format. Files from the draft
  format still import; 1.13.3 and older cannot read the new ones.

No new permissions. Still no host permissions and no content scripts.
