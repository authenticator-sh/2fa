## A password reset no longer hides your new recovery code

This release fixes one bug, and it is a serious one for the people it reached.

**Who was affected.** You had password protection on, you used **Forgot your
password?** with your recovery code, and you did it in 1.12.0 or 1.13.0. The
one exception is an auto-lock setting that asks for the password every time the
popup opens. That setting avoided the bug.

**What happened.** A reset replaces your recovery code, on purpose: the old one
has just been read off paper or out of a file, so it counts as used. The new
code is supposed to appear on a screen you cannot leave until you have typed it
back. Instead, that screen showed for about a twentieth of a second, and you
were taken straight to your accounts. The reset had already been saved, and
saving it unlocked the vault. The popup took the unlock as a reason to replace
the lock screen, and the new code disappeared with it. The code you had used
was no longer valid, and you never saw the one that replaced it. The next time
you forgot your password, the only code you held was refused: "That recovery
code is not valid."

**Your accounts are not lost.** The password you chose during that reset opens
them. What you are missing is a recovery code, and you can get a new one:

1. Open the extension with the password you set during the reset.
2. Export a backup first (Settings → Backup & Restore), and keep it somewhere
   safe.
3. In Settings → Password protection, turn protection off, then turn it on
   again. You will get a new recovery code, and you have to type it back before
   anything is saved.

If you remember neither the password from the reset nor any working code,
nobody can open the encrypted accounts, including us. The encryption is built
so that no one else can. Check whether another computer or an exported backup
still has them.

## What changed

- **Nothing is saved until you have typed the new code back.** The new password
  and the new code are built and checked in memory first. The check opens the
  vault with both of them the same way unlocking does. Only **Finish** writes
  anything.
- **Closing the popup on that screen costs nothing.** Say you click
  **Download as file** and the save dialog takes focus. The reset has not been
  written, so your old password and your old recovery code both still work.
  Start again.
- **A change made in another window stops the reset.** You may leave the screen
  open while you copy the code onto paper. If protection is turned off or set
  up again from another window in the meantime, Finish refuses and saves
  nothing. The message says so and offers a way back. A passkey added in the
  meantime is kept.
- The text on that screen no longer says your password "was changed" before
  anything had been saved. In all twenty languages, it now says the new password
  and the code take effect when you finish.

## How this is covered now

The regression is pinned in `test/vault-safety.test.ts`. The key check: preparing
a reset sends the popup no signal that could read as an unlock, and the stored
vault data stays byte for byte the same. The other checks cover walking away from
the screen, a wrong code, a second click on Finish, a vault that was turned off
or set up again before Finish, and a passkey added before Finish.

The fix was also run in real Chromium against a real encrypted vault. Before
the fix, the new-code screen lasted 54 ms. After it, the screen stayed until the
code was typed back. The spent code was refused, and the new password and the
new code both opened the vault.

## Also in this release

- **A banner for our Product Hunt launch, on 29 September only.** It appears
  above your codes from 00:01 Pacific time for 24 hours. It asks for a comment,
  never a vote. You see it if you have opened the extension at least three
  times or have already rated it, and only while there are accounts on screen:
  never over a locked vault, and never in place of an error or the clock
  warning. Closing it or following its link retires it for good. The link goes
  through `authenticator.sh/producthunt`, so we can repoint it without
  shipping another build. On that day a small dot may appear on the toolbar
  icon when the browser starts, and the first time you open the extension
  clears it. The date is fixed in the build, so the banner turns itself on and
  off with no update.
- **The backup reminder no longer asks right after a restore.** On a fresh
  profile, restoring from a file used to prompt you for a backup within the
  same second. The automatic snapshot had not been written yet, and the
  reminder took that as a sign that none would ever be. Importing also records
  how many accounts you now have. Thirty days later the reminder no longer
  counts every imported account as added since your last backup.
- **The password-manager card under the codes goes away once you follow its
  link.** Before, it stayed and made the same offer on every open.
- **The offer to turn on password protection is counted only when you actually
  see it.** It is shown three times at most. Each showing used to count even
  when another notice covered it. Someone with a backup reminder up on every
  open could spend all three without ever seeing it.

No permissions changed in this release.
