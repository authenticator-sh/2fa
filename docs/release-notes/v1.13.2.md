## The automatic copies are finally reachable

Since 1.10.0 this extension has been taking a copy of your account list once a
day and keeping the last seven. Nothing has ever shown them to you. If your list
went empty — an update that went wrong, an account deleted by accident, a
profile that came back without its data — the only honest answer support could
give was "export more often", while seven copies sat on your own disk with no
way to reach them.

This release opens them.

**Settings → Automatic copies.** Every copy is listed with how many accounts it
holds and how long ago it was taken. Any of them can be put back. It is there
all the time, not only when something is wrong, because the moment you need this
is the worst possible moment to be discovering it exists.

**And where an empty list is.** If your list is empty while a copy holds
accounts, the extension says so above the setup guide and offers to restore it.
You only see that when a copy with accounts in it actually exists — a genuinely
new install has none, so nothing changes for anyone starting out.

The same offer appears on the screen that says your accounts could not be read,
next to **Try again**.

## What restoring does, exactly

**It only ever adds.** Restoring never replaces, renames or removes anything you
have now. Accounts already here keep their name, their group and their position;
only accounts whose key is missing are added back. A copy is up to a day old,
and someone restoring one has usually re-added an account or two by hand
already — that work is not going to be thrown away by a button we offered them.

**Pressing it twice is harmless.** The second time adds nothing and says so.

**Password protection is respected.** The copies hold your records in the same
form as the store itself, so a copy taken while protection was on is encrypted.
Restoring one needs the vault unlocked, and records that belong to a password
set up on another device are counted and reported rather than written back as
unreadable junk. Nothing is ever put back in the clear next to encrypted
records.

## Where the copies live, and where they do not

They are on this computer, in this browser profile. That means:

- Uninstalling the extension removes them. If you might reinstall, export a file
  first (Settings → Backup & Restore).
- Clearing "cookies and other site data" for the browser can remove them too.
- They never leave your device, and they are not part of sync.

They are a safety net for the list going wrong, not a substitute for a backup
file you keep somewhere else. Nothing about that has changed in this release —
it is just now possible to say it and point at something.

## Also in this release

- **A copy that is gone says so.** If a copy is rotated out or wiped while the
  list is on screen — turning password protection on replaces all seven — the
  restore now reports that the copy is no longer there, instead of claiming
  everything in it was already restored.
- **Copies from a build that never recorded a count** are measured from their
  own records, rather than describing themselves as empty and offering no way
  back.
- **A restored account can no longer collide with an account already here.**
  Account ids survive an export and an import, so two records could arrive
  carrying the same one — and deleting either would have deleted both. A
  restored account that finds its id taken is given a fresh one.

No permissions changed in this release. The store rollout follows separately, so
this version may be here before it reaches your browser.
