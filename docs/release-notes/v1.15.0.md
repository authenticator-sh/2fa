## Cloud backup, with Pro

Losing the computer no longer has to mean losing your codes. With Pro, the
extension keeps an encrypted copy of your accounts on our server, in
**Settings → Backup & Restore → Cloud backup**.

- **Only you can open it.** Turning it on gives you a *backup recovery code*.
  Your accounts are encrypted with it in your browser (AES-256-GCM) before
  anything is sent. The code itself never leaves your browser: our server
  stores the encrypted copy, a short id of the code, and a hash of a second
  value derived from it that proves a device holds the code. We cannot open
  your copies, and we cannot recover them if the code is lost.
- **It keeps itself up to date.** A copy is sent when you turn it on, when you
  press **Back up now**, and when the extension opens and your accounts have
  changed since the last copy that browser sent. The server keeps recent
  copies, one a day for a month, and the newest from each of your browsers.
- **Restoring only adds.** Like the automatic copies on this device, restoring
  a cloud copy adds the accounts that are missing and leaves the rest exactly
  as they are.
- **On a new computer:** activate your license key, then enter the backup
  recovery code. The newest copy is merged in at once, and that browser joins
  the backup. Its own accounts, if it had any the copy lacked, are sent along
  with the copy's — so a new computer's half-filled list never becomes the
  newest copy. Restoring with **Restore from cloud backup with your license
  key** on a browser without Pro turns Pro on there too, while the license is
  active, and that browser keeps backing up.
- **With password protection on**, the recovery code kept in the extension is
  encrypted under your password like your accounts, here and in Chrome sync.
- **If Pro ends**, no new copies are made. The existing ones stay restorable
  for 90 days — on another browser with your old license key and the code —
  and are then deleted. Buying Pro again from a browser that held the earlier
  license takes the backup, code and copies, over to the new license.
- **Turning it off** deletes every copy on the server, those sent from your
  other browsers too. It needs the code: an install id alone cannot wipe your
  backups.
- **Lost the code?** Your license key can start the backup over with a new
  code. The old copies are deleted, since nobody could open them anyway.

## A second style, and Light/Dark in Settings

**Settings → Appearance** has two styles: **Classic**, which is the extension
as it has always looked, and **Modern** — Apple's system greys and blue,
grouped lists and larger corners. The light/dark switch is there too, next to
the moon in the header. Nothing changes until you pick: the extension stays
Classic. The choice applies to the popup, the floating window, the side panel,
the camera page and the passkey page alike.

## What the extension now sends, and when

The check-in described in 1.14.0 gains these, and nothing else:

- **Which style the extension is drawn in, and light or dark.**
- **How adding accounts went, as kinds and counts.** The first time the
  extension is opened and how long after installing; that the "add your first
  account" screen was shown and which way was picked on it; which add screen
  was reached; which error was shown or where adding was left — as a kind,
  such as `error_no_qr` or `camera_denied`, never what was scanned or typed;
  how many accounts were added and by which way; that a code was first copied
  or filled in. Never an account's name, issuer, secret, or the site it is for.
- **That the cloud backup offer in Settings was shown or closed.**
  The list is closed (`src/billing/events.ts`), and a test holds every event to
  it.
- **Sooner for a new installation.** In its first three days, a new
  installation sends those events within minutes instead of with the next
  daily check-in — at most every five minutes — because most people who give
  up do so in their first minutes, and we would otherwise never learn where.
  Installations from before this release do not.
- **The uninstall page** now also carries how far a new installation got
  towards a first account (`installed`, `opened`, `pick:ga`,
  `fail:camera:camera_denied`, `added:scan`, `used`) — the one record of
  someone who leaves between two check-ins.
- **The welcome page** opened on install now carries the install id. The site
  passes it to our server only for a browser that came from one of our ads, so
  we can tell which campaign led to installations that went on to use the
  extension. It never goes to Meta.
- **Cloud backup**, if you turn it on: the encrypted copies described above.

The full list of fields is in the README under "What is sent to our server".

## Also new

- **The Pro screen** names what Pro adds as it now is: as many accounts as you
  need, an encrypted backup in the cloud — and that we cannot see your keys.
  Opened from **Cloud backup → Turn on**, or from the cloud backup offer at
  the top of Settings, it talks about the backup rather than the account
  limit. The offer is shown only where Pro can be bought and to installations
  without it, and once closed it stays closed. If one license needs to cover more browsers than it
  does, write to support@authenticator.sh.

No new permissions. Still no host permissions and no content scripts.
